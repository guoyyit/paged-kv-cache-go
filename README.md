# Paged KV-Cache (Go)

面向本地推理运行时的分页 KV 缓存内存管理器。它把整段连续的键值缓存切成
固定大小的块，在保证读取结果正确、内存占用可控的前提下，提供：

- **分块管理与块级共享（copy-on-write）**：长上下文被切分为固定大小的块；
  相同前缀的块按内容寻址、引用计数共享；任何请求改写共享块时都会写入自己的
  副本，其他请求已见内容不受影响。
- **多租户隔离与配额**：每个租户有独立的私有块配额；一个租户超额、被回收都
  不会挤占或读到另一个租户的块。
- **内存不足时的抢占与换出**：先回收零引用的共享块（LRU），仍然不够时把某个
  运行中的请求整体换出到磁盘；被换出请求可完整恢复，无法恢复时被明确标记为
  “需要重算”，绝不会返回不完整内容。
- **确定性回收顺序**：相同输入下回收顺序确定（LRU 时间戳 + 块/序列 id 打平
  平手）。
- **重启恢复**：提交的块映射以带校验的追加日志记录，块内容以带校验的内容文件
  保存；映射与换出数据在启动时对齐校验。部分写入或损坏的块不会被当作有效缓存
  返回，也不会阻塞启动。
- **并发安全**：分配、共享、改写、换出、恢复可并发进行；单一管理器锁保证任一
  时刻同一块的可见状态自洽，读不到半写内容，同一块不会被重复分配。

## 安装 / 构建

```bash
go build ./...
go test -race ./...
```

## 快速开始

```go
m, err := pagedkv.NewManager(pagedkv.Config{
    DataDir:          "/var/lib/kvcache", // 空串 = 纯内存（无换出/恢复）
    BlockSize:        4096,               // 每个物理块的字节数
    TotalBlocks:      4096,               // 内存中物理块总数
    EvictionPolicy:   "lru",
    PreemptionPolicy: "oldest",           // 或 "priority"
})
if err != nil { log.Fatal(err) }
defer m.Close()

if err := m.RegisterTenant("team-a", 512); err != nil { // 私有块配额
    log.Fatal(err)
}

seq, err := m.NewSequence("team-a", "request-42", 0) // priority=0
// 追加（自动分块、共享前缀、写时复制）
_ = m.Append(seq, tokenBytes)
// 读取（自动恢复被换出的序列）
data, err := m.Read(seq, offset, length)
// 派生：共享已填块，复制当前私有尾块
fork, _ := m.Fork(seq, "request-43")
// 持久化块映射，使其可跨重启恢复
_ = m.CommitSequence(seq)
// 释放：归还私有块、递减共享块引用
m.ReleaseSequence(seq)
```

重启：

```go
m, issues, err := pagedkv.Recover(cfg) // issues 非致命，仅汇报被跳过的损坏记录
```

## 分页与共享语义

- 每个**物理块**固定 `BlockSize` 字节；序列是逻辑块的有序数组。
- 当一个块被**写满**时才“定稿”：对其链式内容键取
  `SHA256(prevKey || blockBytes)`（首块的 `prevKey` 为全零）。
  - 链式键保证：内容相同但前缀位置/前文不同的块不会误共享。
  - 定稿块不可变，进入全局共享缓存并以引用计数绑定到逻辑块。
- 未写满的最后一个块是**私有尾块**，只属于一个序列、不计入共享索引。
  `Fork` 时共享所有定稿块、立即复制私有尾块（copy-on-write）。
- 只有定稿后的全块可能被 LRU 回收；回收后内容仍可按键从磁盘重新读入
  （配置了 `DataDir` 时）。
- 每个序列内部碎片上界恒定为 `BlockSize - 1` 字节（只有尾块可能半空）；
  释放后所有块立即可再次分配，不存在随时间累积的不可回收碎片。

## 配额语义

| 块类型             | 是否计入租户配额          | 可否被其他租户回收 |
|--------------------|---------------------------|--------------------|
| 私有尾块           | 是（占用 1 块）           | 否                 |
| 定稿的共享全块     | 否（全局内容缓存）        | 仅零引用时 LRU 回收 |

- 私有块仅在“未写满的尾块”期间计入租户配额；尾块一定稿即转为共享块并释放
  配额。
- 租户配额耗尽时：优先换出**同一租户**的另一个运行中请求；仍不满足则返回
  `ErrQuotaExceeded`。不会因为一个租户超额去回收另一个租户的私有块。
- 全局物理池耗尽时（所有租户共享的上限）：先 LRU 回收零引用共享块，再根据
  抢占策略整体换出某个运行中的请求。

### 错误原因（`errors.Is` 可区分）

| 错误 | 含义 |
|------|------|
| `ErrTenantNotFound` / `ErrTenantExists` | 租户未注册 / 重复注册 |
| `ErrQuotaExceeded` | 租户私有块配额不足，且没有可换出的同租户请求 |
| `ErrOutOfMemory` | 物理池耗尽，也没有可回收块或可抢占请求 |
| `ErrUnauthorized` | 跨租户访问被拒绝 |
| `ErrOutOfBounds` | 读取越过已写入区间（含负参数） |
| `ErrNeedsRecompute` | 换出状态无法完整恢复，请求必须重算 |
| `ErrCorrupt` | 持久化块/日志校验失败 |
| `ErrNotFound` | 换出键不存在 |
| `ErrSequenceNotFound` / `ErrSequenceExists` | 序列未知 / id 重复 |
| `ErrInvalidArgument` | 非法配置或参数 |
| `ErrNoPersistence` | 未配置 `DataDir` 时调用 `CommitSequence` |

## 淘汰与抢占参数

- `EvictionPolicy: "lru"`：回收零引用共享块时，选择 LRU 时间戳最小的块；
  时间戳相同则按块 id 升序。回收顺序是状态的确定性函数。
- `PreemptionPolicy`：
  - `"oldest"`（默认）：换出创建顺序最早的运行中请求，id 打平。
  - `"priority"`：换出优先级最低的请求；优先级相同按创建顺序、再按 id。
- 抢占以**整个请求**为单位换出所有块；读/写被换出的请求时惰性恢复（恢复
  过程同样会经过配额与内存压力路径），恢复期间任何块缺失或校验失败都会把该
  请求标记为 `seqInvalid`，之后的读返回 `ErrNeedsRecompute`，不会读到半成品。

## 持久化布局与恢复保证

`DataDir` 下：

```
journal.log          # 提交映射的追加日志（帧长 + 类型 + 载荷 + CRC32）
blocks/<hexkey>.blk  # 内容寻址块文件：魔数 + 长度 + 数据 + SHA256
```

- **原子提交**：提交时先把所有块内容写入内容存储（临时文件 + `rename`，
  带 fsync），再把映射写入 `journal.log.tmp` 并原子改名覆盖 `journal.log`。
  崩溃只会暴露“旧的完整映射”或“新的完整映射”，不会暴露部分写入。
- **启动校验**：
  - 块文件魔数、长度、SHA256 任一不符 → 该映射被丢弃并通过
    `Recover` 的 `[]RecoveryIssue` 汇报，绝不作为有效缓存返回。
  - 全块还会重新计算链式键并与日志中的键逐一比对，确保映射与换出数据对齐。
  - 日志尾部损坏/截断只忽略尾部；魔数损坏则整个日志忽略；空目录正常启动。
- 恢复出来的序列初始为“已换出”状态，首次 `Read`/`Append` 时按需加载，避免
  启动时一次性占满内存。

## 并发模型

所有状态迁移在单个管理器互斥锁下完成（磁盘 I/O 也在锁内，规模面向本地单进程
推理运行时）。因此：

- 同一块在任一时刻只绑定一个逻辑属主，不会被重复分配；
- 写满定稿、引用计数增减、LRU 时间戳更新、换出/恢复对外部观测是原子的；
- `Read` 返回的是块内容的拷贝，调用方后续修改不会污染缓存。

查询某个序列是否已被抢占，请使用 `m.SequenceState(seq)`（返回
`StateActive` / `StatePreempted` / `StateInvalid`），不要直接读 Sequence
字段——其他请求的分配可能在任意时刻抢占它。

## 测试

```bash
go test -race ./...
```

覆盖场景：

- 多租户隔离、配额计费、超额不挤占其他租户；
- 前缀块共享、不同前文不误共享、Fork 的 copy-on-write；
- 内存不足时的抢占、换出/恢复往返、无持久化时的“需要重算”路径；
- LRU 回收顺序的确定性、交替长短序列负载下无持续增长的不可回收碎片；
- 提交/重启恢复、缺失块与损坏块被拒绝、日志截断不阻塞启动；
- 高并发下的共享追加、混合读写/Fork/提交（`-race`）与重复分配检查。

## 主要文件

| 文件 | 职责 |
|------|------|
| `config.go` | 配置、默认值、校验、策略常量 |
| `errors.go` | 可区分原因的哨兵错误 |
| `block.go` | 物理块、块状态、链式内容键 |
| `sequence.go` / `tenant.go` | 序列（逻辑块绑定、换出条目）与租户记账 |
| `store.go` | 内容寻址的校验块文件（临时文件 + rename） |
| `journal.go` | CRC32 追加日志的编码与恢复解析 |
| `evict.go` | 确定性 LRU 与抢占策略 |
| `manager_*.go` | 生命周期、追加/COW、读取、Fork、分配回收、换出恢复、提交、重启 |
